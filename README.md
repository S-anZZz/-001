# add work · 在线求职招聘系统

一款类似领英 / Boss / 猎聘的线上求职招聘系统：企业发布职位、求职者投递简历、搜索匹配。

> 2026-11-20：本轮补充的是本地源码中的安全与主流程修复，未部署线上。以下线上访问与证书信息为此前记录，不代表本轮已验证或已更新的线上版本。

## 本轮完善范围

- 安全：关闭回显验证码的公开找回接口；简历和许可证附件按对象授权；敏感文件禁止缓存；CSV 导出防止字符串被解释为公式。
- 职位：修复匹配度、薪资排序、企业投递数与刷新后的编辑操作；停用企业不再出现在职位搜索、推荐、详情或主页中，也不能接收新投递。
- 沟通：独立会话列表，最新消息游标分页、按返回页标记已读、发送回执、双方同意后展示对方电话。
- 面试：双方面试列表、拟议改约时间、企业接受或拒绝改约、状态转换校验及投递轨迹；改约申请不再直接覆盖原时间。
- 审核：密码校验成功后向被驳回企业显示具体原因，管理员可重新审核通过；不会为待审或停用账号创建会话。

本轮未新增公告、举报、免打扰、真实短信或真实会议服务；这些能力不计为已完成。

## 技术栈

- 后端：Node.js + Express + MySQL（`mysql2` 异步驱动）

## 功能

### 求职者

- 注册 / 登录，可维护**多份简历**（每份可设为主简历），扩展字段包含：技能标签、工作经历、项目经历、教育经历、自我评价、期望城市、期望薪资区间、到岗时间、求职状态；项目与教育经历目前仍为文本。
- 简历**开放度**（公开 / 仅投递可见 / 隐藏），每次修改留存快照；历史接口目前仅返回修改时间，不支持恢复历史版本。
- 收藏职位、关注企业。
- 投递记录支持**按状态/关键词筛选与按时间或匹配分排序**（当前在最近 200 条记录内筛选），可查看状态、面试及企业通过投递附件入口查看/下载的轨迹；同一企业同类附件操作只记录首次发生。
- 同一职位**可重复投递**：记录按职位累计，列表展示「投递次数」，再次投递会刷新状态并追加轨迹。
- 收到面试邀约后可**确认、改约或拒绝**；改约保留原时间并等待企业处理，接受后才生效，拒绝后返回原时间等待求职者确认。
- 按关键词、地点、薪资、学历、经验搜索职位
- 投递简历，查看投递状态与匹配分、匹配理由
- 接收面试通知与站内消息
- **聊天独立成页**：左侧是联系人列表（展示企业/求职者与最近一条消息、未读数），点选即切换右侧会话，可直接回复并回看历史消息，无需先交换联系方式。
- **交换联系方式**与聊天分离：请求统一进入「消息通知」页处理（同意 / 拒绝 / 先聊聊），同意后才展示对方电话。

### 企业

- 注册（填写企业名称、用户名、密码、联系人，可上传头像与经营许可证；提交后需管理员审核通过才能登录）
- 发布 / 编辑 / 下架职位（提交后立即进入职位库，无需管理员审核）
- **收到的简历**支持按状态归档（待查看 / 已查看 / 待面试 / 已录取 / 不通过，带数量统计），可逐条标记状态、查看附件，并**删除**不再需要的投递记录
- 查看收到的简历，筛选候选人，更新投递状态
- 发送线上面试邀约（腾讯会议 / 钉钉 / 飞书 / 企业微信，当前为可插拔模拟实现）
- 处理交换联系方式请求，可主动「发布联系方式」并弹出聊天窗口与求职者沟通

### 管理员

- 账号：`admin / root123456`
- **运营看板可下钻**：点击统计卡片进入用户、企业、职位管理页，支持搜索、启用/停用、置顶/急招、上下架与删除（增删改查）
- 审核企业注册申请（通过后企业方可登录），驳回需填写理由
- 管理用户账号（启用 / 停用）

## 账号与验证

- 注册只需**用户名 + 密码（4~8 位）+ 姓名**；企业注册额外填写公司名称与经营许可证（可选），并需管理员审核通过后才能登录；
- **手机号可选**：注册与企业资料修改会检查格式及已有号码占用；手机号未验证所有权，只能作为联系电话，不能作为找回凭据，数据库尚无手机号唯一约束；
- 登录页保持无「忘记密码」入口；`POST /api/auth/code`、`/api/auth/forgot`、`/api/auth/reset` 均返回 **503**，不生成、不回显、不消费验证码，也不修改密码；
- 当前未接入短信网关，也没有管理员重置密码界面。启用自助找回前必须补齐真实验证、已验证手机号绑定、验证码限频与一次性消费；不能重新开放演示回显接口；
- 密码使用**随机盐 + scrypt** 哈希，登录令牌 7 天过期且支持多设备并存。

## 企业端能力

- **企业资料管理**：公司名、联系人、电话、头像、行业、规模、地址、公司简介，审核通过后带“已认证”标识；
- **企业主页**：`GET /api/company/:id` 对外展示企业信息与在招职位；
- **人才库**：按技能、期望城市、学历、期望薪资、关键词检索全站**公开简历**，可直接发起沟通；
- **推荐候选人**：按最近发布的职位与简历的匹配分排序推荐；
- **职位运营**：刷新、置顶、急招、批量下架，列表展示真实投递数；后端保存编辑快照，暂未提供职位历史浏览页面；
- **面试管理**：查看候选人、职位、时间和双方备注；处理改约申请，通过投递轨迹查看邀请及后续处理历史；
- **招聘看板**：职位曝光、投递漏斗（投递→面试→录用）与转化率；
- **职位结构化**：职位类型（全职/兼职/实习/远程）、技能快选标签、福利标签、JD 模板。

## 管理端能力

- **数据看板**：用户/企业/求职者、职位/在招/急招、投递/面试/录用、近 7 天投递；
- **操作日志**：记录所有写操作（谁、什么时候、调用了哪个接口、状态码）；
- **数据导出**：投递、职位、用户三类 CSV（带 BOM，Excel 直接打开不乱码）；
- **企业审核**：可查看经营许可证，通过后自动打认证标记。

## 搜索与推荐

- 职位列表支持**匹配度排序**（按求职者主简历计算），置顶职位优先展示；
- 求职者首页有“为你推荐的职位”，企业首页有“为你推荐的候选人”，均为双向匹配；
- 职位详情页提供**相似职位**推荐，并统计浏览量。

## 体验与合规

- 职位发布支持**技能快选**与**模板**，减少自由文本导致的匹配偏差；
- 聊天有**快捷回复模板**、**未读角标**和**发送消息已读/未读回执**；默认显示最新 50 条，可加载更早消息，只有返回页内的收到消息被标记已读；通过刷新按钮更新新消息与回执，暂不实时推送；
- 简历支持**在线预览**（新窗口，可直接打印/另存 PDF）；
- 注册页提供《用户协议与隐私政策》，说明数据采集范围与简历可见性；
- 内容审核：职位描述与站内消息**敏感词过滤**；
- 限频：同一 IP 每分钟最多发送 30 条站内消息；
- 健康检查：`GET /healthz` 返回数据库连通性与运行时长；
- 企业审核支持**驳回理由**：企业使用正确密码尝试登录时可查看原因，但不会获得会话；需联系管理员补交资料后，由管理员“重新审核通过”，自助补交页面尚未提供。

## 安全与可靠性

- 密码使用**随机盐 + scrypt** 哈希存储（旧版固定盐哈希在登录成功时自动升级），并拦截 `1234`、`abcd` 等弱口令；
- 登录令牌写入 **sessions 表**、有效期 7 天，支持多设备并存；通过 **HttpOnly + SameSite Cookie** 恢复会话。登录响应仍包含保存在前端内存中的令牌，因此 Cookie 设置不能代替 XSS 防护；
- 受保护请求会校验账号状态：管理员封禁或企业仍待审核时，旧令牌不能继续通过鉴权；
- 同一用户名 5 分钟内密码错误 5 次将被临时锁定（进程内计数，适合单实例部署）；
- 业务查询使用参数化占位符处理用户输入，动态排序等片段通过白名单选择；系统异常只写服务端日志，前端统一看到“服务器内部错误”；
- 接口按角色鉴权：未登录返回 **401**、越权返回 **403**；
- 附件下载**必须登录并通过对象授权**，文件名走白名单校验，返回 `Cache-Control: private, no-store`；许可证只允许所属账号与管理员访问，头像允许登录用户访问；
- 简历附件：本人和管理员可读；有效企业可读有效求职者的公开简历，“仅投递可见”仅允许收到该份简历的企业读取；**隐藏简历禁止所有企业访问**，包括此前投递的企业。隐藏简历不能继续投递，需先调整开放度；
- 简历替换附件后，原文件如果已无当前简历引用，普通用户不能继续使用旧链接；可见性变更不能撤回他人已经下载到本地的副本；
- 上传做**扩展名白名单 + 文件头校验 + 大小限制**（头像 ≤2MB、简历附件与许可证 ≤5MB）；基础文件头检查不等同于病毒检测或完整文档格式验证；
- 响应头包含 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` 与基础 CSP；
- 聊天读取接口**不返回手机号**；电话仅由本人主动发送，或在交换请求被对方明确同意后，向该请求双方展示；
- 交换请求的同意/拒绝、面试邀约和改约处理使用事务；重复确认或不允许的状态转换返回 **409**。企业投递附件入口按投递归属校验并对首次查看/下载留痕；
- CSV 导出对文本公式前缀加单引号防护，仍保留正常数值字段；
- 投递在数据库层有 `(seeker_id, job_id)` **唯一索引**兜底，并发下也不会产生重复投递。

## 匹配推荐

投递时根据简历技能标签与职位要求进行简化匹配打分，展示匹配理由：

- **技能 60 分**：按技能覆盖率计分（命中数 / 要求数），分词后精确比对，`Java` 不会误命中 `JavaScript`；`React.js` 与 `React` 视为同一技能；
- **经验 20 分**：简历年限达到职位门槛才得分，并给出「4 年 ≥ 要求 3 年」这样的具体理由；
- **学历 20 分**：按博士/硕士/本科/大专等级比较，不满足时同样写明差距。

职位检索支持关键词、地点、薪资、学历、经验筛选，并支持按最新发布 / 薪资高低排序与**分页**（每页 10 条）。

## 数据表

- 用户表 `users`：ID、角色、认证状态、头像、经营许可证、令牌等
- 简历表 `resumes`：用户 ID、结构化字段（期望薪资/城市/到岗时间/求职状态）、项目经历、开放度、主简历标记、附件
- 职位表 `jobs`：企业 ID、标题、要求、薪资、状态
- 投递表 `applications`：简历 ID、职位 ID、状态、匹配分、面试链接
- 联系方式表 `contact_requests`
- 消息表 `messages`：站内聊天记录（发送方、接收方、内容、已读标记）
- 面试表 `interviews`：面试时间 `scheduled_at`、拟议改约时间 `proposed_at`、方式、链接、状态、双方备注（`seeker_note` / `company_note`）；处理历史写入 `app_events`
- 收藏表 `favorites` / 关注表 `follows`：职位收藏与关注企业
- 简历历史表 `resume_history`、投递轨迹表 `app_events`
- 通知表 `notifications`：含已读标记，支持未读计数与一键已读
- 文件表 `files`：上传的头像与简历附件（`FILE_STORAGE=db` 时启用，保证实例重启后文件不丢）

## 数据库配置

应用默认连接本机 MySQL：

- 主机：`127.0.0.1`
- 端口：`3306`
- 用户：`root`
- 密码：`808080`
- 数据库：`add_work`

可通过环境变量覆盖：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DB_HOST` | `127.0.0.1` | 数据库主机 |
| `DB_PORT` | `3306` | 端口（TiDB Cloud 为 `4000`） |
| `DB_USER` | `root` | 用户名 |
| `DB_PASSWORD` | `808080` | 密码 |
| `DB_NAME` | `add_work` | 库名 |
| `DB_SSL` | 关闭 | `true` 启用 TLS 1.2+，云数据库必须开启 |
| `FILE_STORAGE` | `disk` | `disk` 写本地目录；`db` 存进 `files` 表（PaaS 上必须用 `db`） |

完整示例见 [.env.example](./.env.example)。

首次启动会自动建库、建表并写入演示数据（管理员、演示企业、演示求职者、演示职位）。

### 升级注意

- 新增面试列 `proposed_at`、`company_note`，初始化会按列是否存在进行补充。

## 本地 Tomcat 部署

```bash
./tomcat/start.sh   # 启动 Node(3000) + Tomcat(8081)，带就绪自检
```

| 地址 | 说明 |
| --- | --- |
| http://localhost:8081/ | 应用首页（Tomcat 托管） |
| http://localhost:8081/api/jobs | 接口经 Tomcat 反向代理到 Node |

## 界面设计

前端没有引入任何框架与构建工具，只用 `public/index.html` + `public/style.css` + `public/app.js` 三件套，改版也只动这三个文件。

### 设计基调

沿用项目既定的"黑白块面 + 细线条 + 表格化信息"路线，但把间距、层级、状态表达全部规范化：

| 元素 | 规范 |
| --- | --- |
| 配色 | 纯黑白灰阶，`--ink-900`（墨）→ `--ink-050`（浅底）共 8 档，不使用彩色 |
| 结构色块 | 一级卡片标题为黑色块（带 7px 方形标记），嵌套卡片改为浅灰条，形成层级 |
| 线条 | 结构线用纯黑 `#0d0d0d`，常规描边 `#d9d9d4`，表格数据行用更弱的 `#e9e9e4` |
| 圆角 | 2～10px 分级，整体克制，不做大圆角 |
| 字体 | 系统字体栈（PingFang SC / Microsoft YaHei），数字统一 `tabular-nums` 等宽 |
| 动效 | 统一 160ms `cubic-bezier(.4,0,.2,1)`，只用于悬停、按下与弹窗入场 |

所有颜色、圆角、阴影、间距、字号都写在 `public/style.css` 顶部的 `:root` 变量里，改主题只需改变量。

### 组件词汇表

全站只有下面这些组件类名，新增页面请复用，不要另起同名不同物的写法：

| 类名 | 用途 | 说明 |
| --- | --- | --- |
| `.card` / `.card-head` / `.card-body` | 卡片容器 | 一级标题为黑块，嵌套卡片自动降级为浅灰条 |
| `.nav` | 仪表盘主导航 | 下划线式，粘在顶栏下方；分段控件另用 `.seg` |
| `.seg` | 分段控件 | 登录 / 注册切换等二选一场景 |
| `.badge[data-s]` | 状态徽标 | 用 `data-s` 承载语义，靠黑白深浅表达状态 |
| `.score` | 匹配分徽章 | ≥80 填黑、≥60 描边、其余淡灰 |
| `.notice` | 通知条目 | 类型 + 时间 + 正文三段式，未读加浅底 |
| `.form-section` | 表单分节标题 | 方块标记 + 细分隔线，`h4` 为主标题、`h5` 为分节 |
| `.table-wrap` | 表格滚动容器 | 窄屏时表格内部横向滚动，不撑破页面 |
| `.toolbar` / `.spaced` / `.hint` | 布局小工具 | 按钮条、上下留白、提示文字 |
| `.empty` | 空态 | 统一细线方框标记 + 文案 |
| `.modal-md` / `.modal-lg` | 弹窗尺寸 | 职位详情 / 附件预览 |

### 主要改进

- **登录页**：整页收敛成**一块黑色面板**——左侧品牌叙述、右侧登录表单同处一个块面内，中间只用一条竖向细线分隔，不再是"黑卡 + 白卡"两块拼贴。表单控件同步改成深色（半透明输入框、白色描边、白底黑字主按钮），与黑底属于同一套视觉语言；窄屏时表单置顶、品牌介绍在下，同样保持在一块面内。
- **顶栏**：粘性顶栏 + 毛玻璃背景，登录后显示「头像 / 姓名 / 角色」胶囊，无头像时用姓名首字占位。
- **导航**：主导航由原来的方框页签改成下划线式（粘在顶栏下方），当前项黑色下划线 + 加粗；登录/注册用独立的分段控件（`.seg`）区分，不再与主导航共用类名。
- **表格语义化**：全部 15 张表格改为 `<thead>` + `<tbody>` 结构，表头单元格带 `scope="col"`，既方便读屏，也支撑表头吸附。
- **粘顶表头**：桌面端表格随页面滚动时，表头固定在导航正下方（偏移量按导航实际高度 44px 计算，与导航严丝合缝）；窄屏表格在容器内横向滚动，此时关闭粘顶避免错位。
- **表格**：统一表头浅灰块、数据行弱横线、斑马纹与悬停高亮；长文本（职位要求、匹配理由）超宽自动省略并保留 `title` 悬浮全文；薪资、投递数等数值列右对齐并用等宽数字。
- **表格滚动**：所有表格自动套上 `.table-wrap` 容器（`MutationObserver` 监听异步渲染），窄屏时表格内部横向滚动，页面本身不再被撑破。
- **状态徽标**：用 `data-s` 承载语义（已录用 / 面试中 / 未通过 / 待审核…），靠黑白深浅表达状态，不靠颜色；匹配分另用圆角分数徽章，80 分以上填黑、60 分以上描边。
- **表单**：统一 38px 控件高度、自定义下拉箭头、聚焦黑色描边 + 3px 光环；文件上传改成虚线框 + 按钮样式；长表单按语义分节（简历表单分「基本信息 / 求职意向 / 技能与经历 / 自我评价与附件」，职位表单分「岗位信息 / 薪资与要求 / 技能与发布」），小节标题沿用方块标记语言。
- **弹窗**：聊天、职位详情、附件预览统一为带阴影的圆角卡片，遮罩加毛玻璃，入场有 200ms 缩放淡入；三种尺寸收敛为 `.modal-md` / `.modal-lg` 两个类，不再写内联宽度。
- **零内联样式**：除表单显隐这类必须由 JS 控制的 `display` 外，页面里不再有 `style="..."`，间距与尺寸一律由类名控制。
- **简历预览**：新窗口打印页重做为 A4 版式（细线分隔、技能标签化、可直接另存为 PDF）。

### 响应式断点

| 断点 | 变化 |
| --- | --- |
| > 1000px | 登录页为一块黑色面板，左右两栏等高铺满视口高度 |
| ≤ 1000px | 登录页上下堆叠（表单在前）；表格转为内部横向滚动 |
| ≤ 760px | 筛选条件两列；表格禁止单元格折行、关闭粘顶表头；导航横向滚动 |
| ≤ 520px | 顶栏隐藏副标题与用户名，仅留头像与退出 |

## 课程报告与图件流水线

三份 Word 报告（主报告 + 两份个人版）共用同一套 9 张正文插图：4 张黑白技术风示意图 + 5 张界面实拍截图。

图件全部由 `_report/figs/` 下的脚本生成，**不依赖任何图形工具链**（本机没有 rsvg-convert / inkscape / cairosvg / ImageMagick），统一走 HTML/CSS → Edge headless → PNG：

| 脚本 | 作用 |
| --- | --- |
| `render.py` | Edge headless + CDP 渲染器：按目标尺寸输出 PNG（示意图 1800px 宽，截图 1440×950 / 390×844） |
| `fig-style.css` / `fig-connect.js` | 示意图共用的黑白技术风样式与「按实际布局计算连接线」的画线助手 |
| `fig2-1-function.html` 等 4 个 | 功能结构图、招聘流程图、E-R 图、技术架构图（架构图含 Tomcat → Node → MySQL 链路） |
| `replace_media.py` | 按图注定位，把 docx 内 `word/media/` 的图替换成新图；新图与原图像素尺寸一致，`wp:extent` 无需改动 |
| `make_toc_field.py` | 把目录整理成 Word 动态 TOC 域（`TOC \o "1-2" \h \z \u`，dirty），页码由 Word 打开时自动更新 |
| `preview_figs.py` | 生成「图件落位预览」页，用于核对图号、图题与所属章节是否对应 |

重新生成流程：

```bash
# 1) 渲染图件（示意图 + 界面截图）
cd _report/figs && ../.venv/bin/python render.py jobs-diagrams.json
../.venv/bin/python render.py jobs-screens.json

# 2) 重建主报告：先还原模板，再按 content.py 装配，最后整理目录域
cp _report/原报告备份.docx "../《Java Web课程设计》报告.docx"
../.venv/bin/python build_report.py
../.venv/bin/python figs/make_toc_field.py "../《Java Web课程设计》报告.docx"

# 3) 两份个人版：按图注替换图片，结构与分页保持不变
../.venv/bin/python figs/replace_media.py "../《Java Web课程设计》报告_赵依帆版.docx" figs
../.venv/bin/python figs/replace_media.py "../《Java Web课程设计》报告_周杰版.docx" figs
```

> 报告文档与 `_report/` 目录按本仓库约定不纳入版本控制（见 `.git/info/exclude`），仅作为本地产物保留。
